# 遥想星空原结构真实机械包络：Linux 证据审计

## 工程问题与当前判定

本工作包只回答：Phase 3 的正常连续分支在真实三维实体中是否无干涉，以及
把四个 4010 的几何替换为官方 EduLite 05 后还剩多少连续机械行程。

当前判定是 **`BLOCKED_BEFORE_COLLISION_SCAN`**，不是 `CLEAR`，也不是
`NOT CLEAR`。原因很具体：原始 SolidWorks 总装文件和全部引用零件都存在，
但目前可用的 Linux 开源读取链尚未可靠恢复总装的实例变换和可用于碰撞计算
的精确实体。没有这些数据，任何“70--120 mm 无碰撞”的结论都会是猜测。

因此本阶段尚未达到完成标准，原 CAD 和 EduLite 替换后的无碰撞区间都保持
为未知。

## 已取得的可靠证据

### 固定输入没有缺文件

原始总装固定为上游提交
`e2444395dd3a76c20b0683fbb1e123c21186a502` 的
`solidworks/总装.SLDASM`，文件大小 `35,513,640 B`，SHA-256 为：

```text
24fdfd78dad6243235ad09fe32328f37442979fbae6191bfd7d7b444b13a299d
```

Linux 原生元数据解析读到一个“默认”配置、76 个实例，隐藏和压缩实例均为
零。其中五连杆碰撞相关的主要数量为：4010 电机 4、关节电机支架 4、大腿
4、小腿 4、大腿垫高 2、推力轴承 6、604 轴承 6、车轮 2、轮胎 2、底板 1。
原文件记录的旧绝对路径虽然失效，但引用名称都能对应到上游目录内实际文件。

这证明“源包和 BOM 完整”，不证明实例位置、配合、实体拓扑或运动无碰撞。

### EduLite 输入来自官方可追溯 STEP

EduLite 05 几何固定为 RobStride 官方产品资料提交
`6ad12f50006273b7ea4eea88980f927d97c22f0d` 中的 `EL05/el05.stp`，
SHA-256 为：

```text
3c970be58644420e97a332473e9b1d806601125c9e95c95743ddeb0c99e27ee3
```

该 AP203 文件能被两个独立的 OpenCascade 前端读取，包含 18 个有效实体。
这足以作为后续机械替换的商品执行器几何输入；但尚未定义它相对原主动轴的
安装变换、法兰适配件和线束 keep-out，因此还不能执行替换碰撞扫描。

### Phase 3 已精确转换成 CAD 姿态表

[`cad_postures.csv`](../../artifacts/mechanical_envelope/cad_postures.csv)
不是重新求一套近似运动，而是直接调用已验证的 Phase 3 正常分支。表中给出
初扫时每 1 mm 腿长对应的两个主动角、两根长杆方向以及 A/B/C/D/E 五个轴心
坐标：

- `47--69 mm`：短端探索；
- `70--120 mm`：优先 baseline，共 51 个姿态；
- `121--152 mm`：长端探索。

46 mm 和 153 mm 没有写入，因为它们已经越过数学开区间
`46.0977 < l0 < 152.0691 mm`。这张表解决了“数学路径如何驱动 CAD”的
问题，但没有替代实体几何。

## 为什么当前转换结果不能使用

`openswx@30bd638` 能稳定恢复文档类型、配置、BOM 和引用状态，但其数据模型
不包含本任务所需的实例变换与 B-Rep。

`cadmpeg 0.5.3@ab0bc65` 能从单个 `SLDPRT` 解出部分 Parasolid 拓扑和显示
三角化，但不支持 `SLDASM` 组件装配。对“大腿”零件生成的 STEP 即使工具
自身报告成功，仍有未证明的 p-curve 关系和拓扑替代：

- FreeCAD/OpenCascade 读取后 `isValid() == false`；
- 另一套 OpenCascade 读取路径直接以段错误退出。

因此它只能作为逆向诊断工具，不能进入碰撞证据链。显示三角网格虽然存在，
但其中一部分无法关联回实体面，而且总装变换仍缺失；把它们拼起来也不能
满足“可靠 CAD / 几何证据”的完成标准。

## 合格输入的最小要求

后续不需要重建参数化特征，也不强制保留原配合。需要的是一个 Linux 可读、
通过验收的中性总装：

1. 优先 AP242（AP214 也可）STEP assembly，保留实例树、实例名和保存姿态
   的 occurrence transforms；等价的精确 B-Rep 总装格式也可。
2. 76 个未压缩实例必须全部存在，或对被有意排除的紧固件逐项说明。
3. 电机、支架、底板、大小腿、垫高件、轴承、轮和轮胎必须导入为有效实体，
   不接受只有包围盒、截图或无法追溯的简化外形。
4. 导入后先在 `70/90/120 mm` 三个姿态核对轴心距离、左右镜像、轴向层叠和
   总装截图；任何轴心配准误差都必须先解释，不能靠放大碰撞容差掩盖。

目前最直接的 Linux 获取路径是具有原生 SolidWorks reader 的 CAD Exchanger
Lab/SDK。官方说明其 Linux 版本可读取 SOLIDWORKS、保留结构和几何并导出
STEP，但下载和评估许可需要账户提供，当前机器上无法匿名完成这一授权步骤。
FreeCAD 已安装并可承担得到合格中性文件之后的实体有效性、距离和布尔检查；
FreeCAD 本身不读取这些原生文件。

## 得到合格输入后的碰撞方法

中性总装的保存姿态只用于建立每个实体的局部坐标和轴向层叠。运动不依赖
原 CAD 配合求解器：从总装中识别 A/E 主动轴、B/D 从动轴和 C 轮轴后，按
`cad_postures.csv` 对每根刚体施加 Phase 3 的解析姿态，并对整机两侧的镜像
五连杆同时检查，而不是只检查二维杆线或单侧零件。

每个姿态采用两级检查：

1. 包围盒只做 broad phase，不生成结论；
2. 对候选实体对做精确 B-Rep 最小距离和公共体积计算，同时记录实体名称、
   `l0`、最小间隙和干涉体积。

轴承/轴、螺栓/孔、轮胎/轮毂等设计接触必须列入显式排除表，不能把所有相交
统一忽略。原始几何先以 1 mm 步长扫 `70--120 mm`，确认流程和三处人工复核
一致后再扩展到 `47--152 mm`。若发现首次接触，必须在最后一个 CLEAR 和
第一个干涉样本之间继续细分到不大于 0.1 mm；不能把 1 mm 离散样本直接写成
精确机械边界。EduLite 版本则先把官方 18-solid STEP 的输出轴与原主动轴同轴
定位，并把新增适配支架作为真实实体加入，再重复同一姿态表和边界细分。

本阶段只报告原始几何间隙；制造公差、紧固件弹性和线束安全间隙尚无统一
输入，不能擅自用一个“推荐最小间隙”把 CAD CLEAR 升级成实机安全认证。
中性 STEP 通常也不保留原配合的限位语义；因此几何扫描能识别由实体接触形成
的硬止挡，但若总装另有角度/距离 limit mate，仍需由能读取原生配合的 Linux
工具单独列出。在这项证据出现前，主动关节“没有额外硬限位”仍是未知。

## 当前可作与不可作的决策

| 决策 | 当前状态 | 依据 |
|---|---|---|
| Phase 3 数学路径继续作为机械扫描基线 | KEEP | 姿态表已精确复算并覆盖完整中段 |
| 原 50/105/105/50/60 mm 杆长 | KEEP（暂定） | 没有新增证据推翻 Phase 3；机械碰撞仍未知 |
| 原 CAD 的 `70--120 mm` 无碰撞 | UNKNOWN | 尚未得到合格实体与实例变换 |
| EduLite 05 商品外形作为替换输入 | KEEP | 官方 STEP 可追溯且实体有效 |
| EduLite 替换后连续机械范围 | UNKNOWN | 安装变换、支架和原总装实体链未闭合 |
| 进入执行器动力学或 150 mm 台阶动力学 | NOT YET | 真实连续机械行程仍没有证据 |

最小的下一项投入不是继续写扫描算法，而是取得上述合格 Linux 中性总装输入
或 CAD Exchanger Linux 评估许可。它一旦到位，现有姿态表就能直接驱动原
结构扫描，并把当前两个 `UNKNOWN` 转换成定量区间和具体干涉实体。
